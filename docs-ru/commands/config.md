# `config-example` / `config-gen`

Эти команды помогают создать YAML-конфиг `agsekit`.

## `agsekit config-example [destination]`

Копирует встроенный пример конфига в целевой путь.

- Путь по умолчанию: `~/.config/agsekit/config.yaml`
- Если файл по умолчанию уже существует, команда не перезаписывает его
- Удобно, если вы хотите редактировать YAML вручную, начиная с готового шаблона

## `agsekit config-gen [--config <path>] [--overwrite]`

Запускает интерактивный мастер и сохраняет результат в YAML.

Важное поведение:

- Первая VM всегда обязательна
- Дополнительные VM опциональны
- Агенты опциональны
- Mount'ы опциональны
- Глобальные переопределения опциональны и спрашиваются только в самом конце

Порядок мастера:

1. Настройка первой VM: имя, CPU, RAM, диск, install bundles, optional proxy settings, optional port-forwarding.
2. При необходимости добавление дополнительных VM.
3. Настройка агентов:
   - выбор типа агента из TUI-списка
   - выбор имени
   - выбор версии агента; по умолчанию предлагается зафиксированная проверенная версия для этого типа
   - при необходимости ввод `env`
   - при необходимости ввод `default-args`
   - если VM больше одной, назначение агента на одну или несколько VM
   - при необходимости override для `proxychains` и `http_proxy`
4. При необходимости настройка mount'ов:
   - `source`
   - `target`
   - `backup`
   - целевая VM
   - optional restrictions по агентам
   - optional default `.backupignore`
5. При необходимости override глобальных настроек.
6. Выбор пути сохранения и запись YAML.

Сейчас в глобальных override настраиваются:

- `ssh_keys_folder`
- `systemd_env_folder`
- `state_file`
- `portforward_config_check_interval_sec`
- `check_new_version`
- `check_new_version_interval_sec`
- `http_proxy_port_pool`

Примечания:

- Install bundles выбираются чекбоксами и могут остаться пустыми.
- Правила port-forwarding можно добавлять по одному; после каждого правила мастер спрашивает, нужно ли добавить ещё одно правило для той же VM.
- Имена VM должны быть уникальными в рамках одного прогона мастера. Мастер начинает с `agent-ubuntu`, а затем при необходимости предлагает `agent-ubuntu-2`, `agent-ubuntu-3` и так далее.
- Имена агентов тоже должны быть уникальными. Если default name по имени бинарника уже занят, мастер предлагает `name-2`, `name-3` и так далее.
- Версии агентов всегда записываются в YAML явно, даже если вы просто принимаете зафиксированное значение по умолчанию.
- Agent `default-args` сохраняются в YAML-список, разбитый по пробелам.
- Если для proxy override агента ввести буквально `""`, в YAML запишется явная пустая строка; если просто нажать Enter, значение останется унаследованным.
- Если агент назначен конкретным VM, мастер также заполняет `vms.<name>.allowed_agents`, чтобы ограничения VM оставались согласованными с назначениями агентов.
- Без `--overwrite` команда не перезаписывает существующий файл.
